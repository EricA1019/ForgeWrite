## 5. Known Protocol Violations / Deferred Debt

### PV1 — `PermissionRule` ignores config (Open/Closed + data-driven violation)
- **File:** `forgerwrite_mcp/validation/semantic.py:131-170`
- **Problem:** `PermissionRule.__init__` takes boolean params, hardcodes them in `default_validator()`, and `check()` ignores the `permissions: PermissionsConfig` parameter.
- **Fix needed:** `PermissionRule.check()` should read `permissions.require_approval_for_full_file_replace` instead of `self._full_replace`.
- **Priority:** Medium — only affects experiments, not production (approval is correct behavior).

### PV2 — `asyncio.run()` in coordinator breaks async callers
- **File:** `forgerwrite_mcp/coordinator.py:101`
- **Problem:** `SliceCoordinator.run()` calls `asyncio.run(self._generate_operations(...))` which crashes with `RuntimeError: asyncio.run() cannot be called from a running event loop` when called from async code.
- **Fix needed:** Either make `run()` async, or use `asyncio.get_event_loop().run_until_complete()` with proper guarding.
- **Priority:** Low — the MCP server calls `run()` synchronously, so this only affects programmatic Python callers.

### PV3 — MEX drift score 0/100
- **Problem:** All 18 errors are false-positive MISSING_PATH (treats command strings as file paths) and DEPENDENCY_MISSING (only checks `package.json`, not `pyproject.toml`).
- **Fix needed:** Configure MEX for Python projects, or accept the noise.
- **Priority:** Low — the scaffold content is accurate.

## 6. Known Bugs / Failures

### Bug 1 — `asyncio.run()` nested call
- **Symptom:** `RuntimeError: asyncio.run() cannot be called from a running event loop`
- **Trigger:** Calling `coordinator.run()` from within an `asyncio.run(main())` context
- **Workaround:** Call coordinator from synchronous (non-async) code
- **See:** PV2 above

### Bug 2 — PermissionRule ignores config
- **Symptom:** `"Full file replace requires approval"` even when `require_approval_for_full_file_replace = false` in config
- **Trigger:** Any `replace_file` operation
- **Workaround:** Don't use `default_validator()` — build custom validator without `PermissionRule`
- **See:** PV1 above
